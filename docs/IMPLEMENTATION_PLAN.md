# План реализации проекта

## Этап 1. Проектирование данных и метаданных
- выделить сущности: источник, набор данных, атрибут, тип проверки, конфигурация проверки, правило уведомления, запуск, результат;
- спроектировать таблицы хранения метаданных и истории;
- подготовить демонстрационный набор данных.

## Этап 2. Бэкенд и SQL-движок
- поднять FastAPI API;
- реализовать CRUD для метаданных;
- добавить безопасный рендеринг SQL-шаблонов;
- выполнить первые DQ-проверки: not_null, not_blank, unique, accepted_values, numeric_range, freshness_days.

## Этап 3. Интерфейс
- вывести сводные показатели на dashboard;
- реализовать форму настройки проверки;
- реализовать таблицу конфигураций и запуск вручную;
- показать историю запусков.

## Этап 4. Инфраструктура
- собрать сервисы в Docker Compose;
- добавить SMTP sandbox через MailHog;
- зафиксировать сценарий запуска в README.

## Этап 5. Следующая итерация
- добавить scheduler и запуск после обновления таблицы;
- вынести проверки в отдельный worker;
- поддержать несколько источников данных;
- реализовать richer dashboard и drill-down по sample bad rows.
